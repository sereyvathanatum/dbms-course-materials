# Capstone project

In teams of 3–4, you build one database project across the term. You may use the Cambodia data from this course or another public dataset; if you use another dataset, record its source and licence in `proposal.md`. Do not use personal data.

Keep the project in one shared private repository: one team member creates it and adds the others as collaborators, so everyone's commits are visible. Your weekly lab and homework stay in your own repository.

| Week | Sprint |
|---|---|
| 1 | Team, problem and eight questions |
| 2 | Schema v0 and data dictionary |
| 3 | **Checkpoint 1:** proposal, data source and import |
| 4 | Five report queries |
| 5 | Join queries and design problems found |
| 6 | Multi-step queries and peer review |
| 7 | ERD v1 |
| 8 | **Checkpoint 2:** normalized schema v1 and migration |
| 9 | Midterm week: plan the next tasks |
| 10 | Views, procedures, triggers and permissions |
| 11 | **Checkpoint 3:** working app with parameterized queries |
| 12 | Document (MongoDB) part |
| 13 | Three aggregation pipelines and modelling decision |
| 14 | **Checkpoint 4:** Redis feature and demo rehearsal |
| 15 | Final demo, report and individual explanation |

Fill in the templates as you go:

- `proposal.md`: Checkpoint 1
- `design.md`: Checkpoints 2–4
- `report.md`: the final report
- `CONTRIBUTIONS.md`: who did what, with links to commits

Add your own files as you build, for example `schema.sql`, `import/`, `queries/`, `app/` and `results/`.
